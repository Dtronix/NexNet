# NexNet v0.19.0

*Released 2026-10-25*

## Highlights

- **A refused call no longer drops the session.** In 0.18.0, a method that `OnAuthorize` refused with `AuthorizeResult.Unauthorized` sent two results. The caller got `ProxyUnauthorizedException`, then disconnected with `DisconnectReason.ProtocolError` when the second result arrived. Every later call failed.
- **Metrics and session snapshots.** NexNet now reports a `System.Diagnostics.Metrics` meter named `NexNet`. `GetSnapshot()` returns the live state of a session or server.
- **Fewer allocations per call.** A call that waits for its result allocates about 409 B less. A received invocation allocates about 2 B instead of 66 B.
- **Cancellation fixes on the caller path.** A late result can no longer complete another call. A remote method that is canceled now fails the call with `TaskCanceledException`.

---

## Breaking Changes

- **Upgrade clients and servers together.** Results have a new state, 4 (`Canceled`), and a 0.19 server sends it. A 0.18.0 server still sends two results for a refused call.
- **Keep `NexNet` and `NexNet.Generator` on the same version.** The generated authorization guard calls `ServerNexusBase.CheckAuthorization(methodId, methodName, permissions, message, cacheDuration)`. The `invocationId` and `hasReturnChannel` parameters are gone. Code generated by Generator 0.18 doesn't compile against NexNet 0.19, and the reverse is also true.
- **Consume a call's `ValueTask` once.** A proxy call returns a `ValueTask` backed by pooled state. Await it, block on it, or convert it with `AsTask()`, but only once. A second use throws `InvalidOperationException`. Call `AsTask()` first if you need the result more than once.
- **A remote `OperationCanceledException` fails the call with `TaskCanceledException`.** This applies whether or not the method was given a token. In 0.18 the caller got `ProxyRemoteInvocationException`.

## New Features

### Metrics and diagnostics

- **The `NexNet` meter** (`NexusMeter.Name`). It reports active and handshaking sessions, disconnects and their reasons, session duration, rejected connections, frames and bytes sent and received, session budget use, pipes, invocations and large messages. It also counts pipe resets and refusals, busy sessions, dropped credit and aborted large messages. Collect it with OpenTelemetry (`AddMeter("NexNet")`), `dotnet-counters` or a `MeterListener`.
- **Choosing the meter.** `ConfigBase.MeterFactory` selects the `IMeterFactory` the meter comes from. When it is null, one meter is shared by the whole process. NexNet.Asp passes the application's `IMeterFactory`.
- **Tags.** The tags are `nexnet.role`, `nexnet.transport` (`ConfigBase.TransportName`) and reason values. They never carry session IDs or addresses.
- **Cost.** Per-frame counts are plain fields on each session. Sending and receiving cost nothing extra, whether or not a listener is attached.
- **Snapshots.** `GetSnapshot()` on `SessionContext`, `NexusClient` and `NexusServer` returns the session budget, invocations, pipes, large messages and transport counters. For pipes this includes any partially received item and any writer waiting for credit.
- **Clearer warnings.** The `Stalled` warning names what made no progress. Pipe reset warnings are limited to one per 10 seconds per session.

See [Metrics and Diagnostics](../metrics.md).

### Execution context

- Invoked methods run in the execution context of the code that started the session. On a client that is the code that called `ConnectAsync`. On a server it is the code that called `StartAsync` or, with the ASP.NET Core transports, the upgrade request.
- Methods therefore see that code's `AsyncLocal` values, such as `IHttpContextAccessor.HttpContext`, `Activity.Current`, logging scopes and the current culture.
- Each invocation runs in its own copy of the context.

## Bug Fixes

- **A call refused by `OnAuthorize` disconnected the session.** The guard sent an `Unauthorized` result, then the invocation sent a `CompletedResult` for the same ID, and the caller treated that as a protocol error. A refused call now gets exactly one `Unauthorized` result. `AuthorizeResult.Disconnect` sends no result and only disconnects the session. ([#85](https://github.com/Dtronix/NexNet/pull/85))
- **A late result could complete a different call.** A result that arrived after its call had been canceled could complete pooled state that another call was already using. Each call's state is now completed only by the path that removes it. A call canceled after it was sent keeps its ID until the server replies, and the server always replies. ([#91](https://github.com/Dtronix/NexNet/pull/91))
- **A cancellation could arrive before its invocation started.** If the cancellation arrived while the invocation was still queued on the server, it was lost. The invocation is now canceled when it starts. ([#91](https://github.com/Dtronix/NexNet/pull/91))
- **A caller canceling while waiting for invocation credit.** The invocation is now always written once credit has been taken. The caller's token only stops a large argument that is being streamed. ([#91](https://github.com/Dtronix/NexNet/pull/91))
- **Leaked token registrations.** A call's cancellation token registration is released when the call completes. ([#91](https://github.com/Dtronix/NexNet/pull/91))

## Performance

- **Calls that wait for a result.** The proxy method is no longer `async`. It returns a `ValueTask` backed by pooled invocation state, which saves about 409 B per call. Awaits keep the caller's `SynchronizationContext`. ([#91](https://github.com/Dtronix/NexNet/pull/91))
- **Received invocations.** They run on a pooled thread-pool work item instead of `Task.Factory.StartNew`. A client receiving invocations allocates about 2 B per invocation instead of about 66 B. ([#86](https://github.com/Dtronix/NexNet/pull/86))
- **Contended sends.** Sends that have to wait use pooled async state machines.
- A new `BroadcastBenchmarks` measures broadcasts to 16 clients, with the sender and the receivers in separate processes. See [Benchmarks](../benchmarks.md).

## Migration Guide from v0.18.0

### Required Changes

1. **Upgrade `NexNet`, `NexNet.Generator`, `NexNet.Asp` and `NexNet.Quic` together**, on both clients and servers.
2. **Check code that uses a call's `ValueTask` more than once**, for example code that stores it and awaits it twice. Convert it with `AsTask()` first.
3. **Check handlers that catch `ProxyRemoteInvocationException` to detect remote cancellation.** They now get `TaskCanceledException`.

### Optional Improvements

- Remove workarounds for refused calls, such as reconnecting after a `ProxyUnauthorizedException`.
- Collect the `NexNet` meter, and call `GetSnapshot()` when a session seems stuck.
