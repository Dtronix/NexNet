# JavaScript runtime contract (`@dtronix/nexnet`)

This is the contract between the code the generator emits for JavaScript
(`src/NexNet.Generator/Targets/JavaScript/`) and the hand-written runtime (`clients/js/packages/nexnet`). It is
**frozen**: renaming or removing a member, or changing a signature, is a contract change that updates every consumer in
one PR. Adding an
optional member or an optional config property is not a contract change.

Source of truth: the JSDoc in `clients/js/packages/nexnet/src/contract/*.js`. This page explains the shape and the rules;
it does not repeat every member.

## 1. Package and workspace

| Path | Contents |
|---|---|
| `clients/js/package.json` | Private npm workspace root: dev dependencies and scripts |
| `clients/js/packages/nexnet/` | `@dtronix/nexnet`, version in lockstep with the NexNet NuGet package; not published to npm (generated output carries the runtime) |
| `clients/js/tsconfig.json` | Type check and `.d.ts` emit for the runtime (`allowJs`, `checkJs`, `strict`) |
| `clients/js/tsconfig.test.json` | Type check of the runtime plus tests and config files |
| `clients/js/vitest.config.js` | Vitest projects `node` and `browser` (Playwright, Chromium) |
| `clients/js/eslint.config.js` | ESLint flat config |

The package is ESM only (`"type": "module"`), has `"sideEffects": false`, requires Node 22 or later and has **no runtime
dependencies**. The sources are plain `.js` with JSDoc. Their `.d.ts` files are generated by `npm run build:types` into
`packages/nexnet/types/`, which is checked in: `npm run typecheck` fails when they differ from a fresh build
(`scripts/check-types.js`), and the generator embeds them beside the runtime it emits. Regenerate and commit them with
any change to the runtime's JSDoc or exports.

### Scripts (run in `clients/js`)

| Script | Does |
|---|---|
| `npm ci` | Installs the pinned dev dependencies |
| `npm run lint` | ESLint |
| `npm run typecheck` | `tsc --noEmit` over the runtime, then over runtime + tests, then checks that `types/` is current |
| `npm test` | Vitest, `node` project |

The JS gate (run for every change under `clients/js`) is `npm ci`, `npm test` and `npm run typecheck` with `--prefix clients/js`. None of them needs a
browser download.

### Entry points

```json
"exports": {
  ".":      { "types": "./types/index.d.ts", "browser": "./src/browser.js", "node": "./src/node.js", "default": "./src/index.js" },
  "./node": { "types": "./types/node.d.ts",  "node": "./src/node.js" },
  "./diagnostics": { "types": "./types/diagnostics.d.ts", "default": "./src/diagnostics.js" }
}
```

| File | Role |
|---|---|
| `src/index.js` | Platform-neutral API: everything generated code and applications use |
| `src/browser.js` | Browser entry. Re-exports `index.js`; the place for browser-only additions (lifecycle reconnect). The Worker keepalive (§3.3) is feature-detected in platform-neutral code, not added here |
| `src/node.js` | Node entry. Re-exports `index.js`, adds `NodeNexusClient` and exports it **as** `NexusClient` |
| `src/diagnostics.js` | `@dtronix/nexnet/diagnostics`: the leak-audit counters (§3.9). Platform-neutral; not re-exported from the main entries |

**Operational exports.** Beyond the contract classes, `src/index.js` exports the client pool error
`NexusClientPoolConnectionError`; the loggers `CoreLogger`, `ConsoleLogger`, `RollingLogger`, `NexusLogBehaviors` and
`NexusLogLevelOrder`; reconnection (`DefaultReconnectionPolicy`, `DEFAULT_RECONNECT_DELAYS`, `DEFAULT_RECONNECT_REASONS`,
`ReconnectController`); metrics (`NexusMetrics`, `Instruments`, `MetricTags`, `METER_NAME`, §3.10); and the
`diagnostics` namespace (§3.9). The Node entry also exports `NodeNexusClientPool`, and exports it **as**
`NexusClientPool`, like the client. `test/contract.test.js` pins the exported names.

So `import { NexusClient } from '@dtronix/nexnet'` gives the Node-capable client under Node and the WebSocket-only client
in a browser bundle, under the same name. Generated code imports only `@dtronix/nexnet` (or the module name set by the
`ModuleName` target option).

**Browser purity rule.** Nothing reachable from `src/browser.js`, `src/index.js` or `src/diagnostics.js` may import `node:*` or a bare Node
built-in, statically or through a literal dynamic `import()`. `test/entry-purity.test.js` walks the import graph and
fails on any such import, and on any non-relative import at all (zero runtime dependencies). Node-only code lives in
`src/node.js`, `src/contract/node.js` and directories named `node/` (for example `src/transport/node/`), which only the
Node entry imports. ESLint enforces the matching globals: Node globals are visible only in those files, tests and config.

## 3. API

### 3.1 Codec and formatter API (`codec.js`)

`codec.js` re-exports `MsgPackWriter`, `MsgPackReader`, `FormatterRegistry` and `tupleFormatter` from
`src/serialization/`. The main entries also export `NexusSerializationError`, `NexusSerializerOptions`, every
built-in formatter and combinator below, and the Guid helpers. `src/serialization/index.js` additionally exports
`resolveSerializerOptions`, the ext 78 helpers (`PRIMITIVE_ARRAY_EXT`, `ElementKinds`, `readPrimitiveArray`,
`writePrimitiveArray`) and the half helpers (`halfToBits`, `halfFromBits`, `roundToHalf`); these are internal to the
package and not on the main entries. The wire encodings are protocol specification §10; the decoding limits are §11.

**`Formatter<T>`** is `{ write(writer, value): void, read(reader): T }`, a stateless, frozen plain object.

- `write` writes exactly one MessagePack value. It throws `TypeError` for a value of the wrong JS type and
  `RangeError` for one outside the C# type's range; it never throws `NexusSerializationError`.
- `read` reads exactly one value and throws `NexusSerializationError` for input it refuses.
- A formatter of a container (sequence, set, map, tuple, `KeyValuePair`, object, union) calls `reader.enter()` before
  its array or map header and `reader.exit()` after its last element. That is what `maxDepth` counts.

**`MsgPackWriter`** (`new MsgPackWriter({ initialCapacity? })`, default 256 bytes) appends canonical (smallest-form)
MessagePack to a growable buffer. A method that throws leaves the buffer unchanged.

| Member | Writes |
|---|---|
| `writeNil()`, `writeBool(v)` | nil, bool |
| `writeInt(v)` | a safe-integer `number` in its smallest form. The target range (sbyte … uint, checked `long`/`ulong`) is the formatter's job |
| `writeInt64(v)`, `writeUInt64(v)` | a `bigint`, range-checked to int64/uint64 |
| `writeFloat32(v)`, `writeFloat64(v)` | float32 (rounded) and float64 |
| `writeString(v)` | UTF-8 str, or nil for null. A lone surrogate becomes U+FFFD |
| `writeBin(v)` | bin of a `Uint8Array`, or nil for null |
| `writeBinHeader(length)`, `writeExtHeader(type, length)` | (\*) a header only; the caller appends the data with `writeRaw` |
| `writeArrayHeader(count)`, `writeMapHeader(count)` | array and map headers (count 0 … 2^32 − 1) |
| `writeExt(type, data)` | ext of type −128 … 127 |
| `writeRaw(bytes)` | bytes as they are: already-encoded MessagePack, or the data after a header |
| `length`, `toUint8Array()`, `reset()` | bytes written; a view valid until the next write or `reset`; clear and keep the capacity |

**`MsgPackReader`** (`new MsgPackReader(source, options?)`) reads one `Uint8Array` or an array of segments (not copied;
do not change them while reading), hardened by `SerializerOptions`. Every read checks the bytes it needs, and counts
and lengths are checked against the remaining input before anything is allocated.

| Member | Reads |
|---|---|
| `options`, `remaining`, `consumed`, `depth` | (\*) the resolved options; bytes left; bytes read; current nesting |
| `peekCode()`, `isNil` | (\*) the next type code / whether it is nil, not consumed |
| `tryReadNil()`, `readNil()` | consumes nil when present / requires it |
| `readBool()` | bool |
| `readInt()` | any integer form as a `number`; `range` when not a safe integer |
| `readSByte()`, `readByte()`, `readInt16()`, `readUInt16()`, `readInt32()`, `readUInt32()` | (\*) any integer form, range-checked to the C# type (`range`) |
| `readInt64()`, `readUInt64()` | a `bigint`, range-checked |
| `readFloat()` | float32, float64 or any integer form as a `number`; the caller rounds to float32 or half |
| `readString()` | a string, or null for nil; invalid UTF-8 is `utf8` with `strictUtf8`, U+FFFD otherwise |
| `readBin()`, `readBinHeader()`, `readBytes(n)` | bin as a new array, or null for nil (str forms accepted); (\*) the length or −1 for nil; `n` raw bytes as a new array |
| `readArrayHeader(expected?)` | the count; with `expected`, a different count is `count`. Counts toward `maxElements` |
| `readMapHeader()` | the entry count; each entry counts its key and its value toward `maxElements` |
| `readExt()`, `readExtHeader()` | `{ type, data }` with a new array; (\*) `{ type, length }` |
| `skip()` | one complete value, iteratively; counts neither depth nor elements |
| `readRaw()` | (\*) one complete value's bytes as a new array (an embedded value carried as is) |
| `enter()`, `exit()`, `ensureEnd()` | (\*) one nesting level (`depth` past `maxDepth`); leave it; `trailing` unless every byte was read |

**`NexusSerializationError`** (extends `NexusError`, mirrors C# `NexusSerializationException`) is what readers and
formatters throw for input they refuse. Its `kind` is a `SerializationErrorKind`, the error kinds of the golden format
(`tests/golden/README.md`):

| `kind` | Meaning |
|---|---|
| `truncated` | the input ends inside the value |
| `type` | a MessagePack type the expected type cannot be read from (nil for a value type, a float for an integer, …) |
| `reserved` | the never-used code `0xc1` |
| `range` | an integer outside the target type |
| `count` | an array with the wrong number of elements for a fixed shape |
| `size` | a wrong byte length for a fixed-size bin or for ext 78 data |
| `length` | a declared str/bin/ext length or array/map count larger than the remaining input |
| `elements` | more elements than `maxElements` |
| `depth` | more nesting than `maxDepth` |
| `utf8` | invalid UTF-8 with `strictUtf8` |
| `value` | a well-formed but invalid value (a date out of range, a decimal scale above 28, an unknown union tag, …) |
| `trailing` | bytes after the value |

**`SerializerOptions`** (C# `NexusSerializerOptions`, spec §11) is `{ preset?, maxDepth?, maxElements?, strictUtf8? }`.
`preset` picks the base values and explicit fields override them; `resolveSerializerOptions(options)` applies them
and throws `RangeError` for a negative or non-numeric limit. The presets are `NexusSerializerOptions.Untrusted` (the
default: `maxDepth` 64, `strictUtf8` true) and `NexusSerializerOptions.Trusted` (`maxDepth` unlimited, `strictUtf8`
false). On a bare reader `maxElements` 0 (both presets) means no limit. **The session supplies the default** ([#226](https://github.com/Dtronix/NexNet/pull/226)): it
resolves `ClientConfig.serializerOptions` with an unset `maxElements` (undefined, null or 0, meaning "use the
default", as in C# `ConfigBase.SerializerOptions`) replaced by `max(65536, maxMessageSize / 16)`, so every reader the
session creates (invocation arguments and results, channel items) is bounded. An explicit positive value
is used as is.

**Built-in formatters** (`src/serialization/formatters.js`). Value types (C# structs) are never nil: reading nil throws
`type` and writing null throws `TypeError`; wrap them in `nullableFormatter` for `T?`. Reference types map nil to and
from `null`.

| C# | Formatter | JS value |
|---|---|---|
| `bool` | `boolFormatter` | `boolean` |
| `sbyte`, `byte`, `short`, `ushort`, `int`, `uint` | `sbyteFormatter`, `byteFormatter`, `int16Formatter`, `uint16Formatter`, `int32Formatter`, `uint32Formatter` | `number`, range-checked both ways |
| `long`, `ulong` | `int64Formatter`, `uint64Formatter` | `bigint` (the default) |
| `long`, `ulong` (checked number) | `int64NumberFormatter`, `uint64NumberFormatter` | safe-integer `number` (below) |
| `float`, `double`, `Half` | `float32Formatter`, `float64Formatter`, `halfFormatter` | `number` (float32 rounds with `Math.fround`; `Half` rounds to the nearest half, written as float32) |
| `char` | `charFormatter` | a 1-unit `string` (a lone surrogate included) |
| `string`, `Uri` | `stringFormatter`, `uriFormatter` | `string \| null` |
| `byte[]`, `Memory<byte>` and the other byte buffers | `binFormatter` | `Uint8Array \| null` |
| `decimal` | `decimalFormatter` | `NexusDecimal` |
| `DateTime`, `DateTimeOffset`, `TimeSpan`, `DateOnly`, `TimeOnly` | `dateTimeFormatter`, `dateTimeOffsetFormatter`, `timeSpanFormatter`, `dateOnlyFormatter`, `timeOnlyFormatter` | the value types of §3.2 |
| `Guid` | `guidFormatter` | lower-case "D" `string` (writes accept "D", "N" and "B" in any case) |
| `BigInteger` | `bigIntegerFormatter` | `bigint` |
| `Version` | `versionFormatter` | `NexusVersion \| null` |
| an embedded raw value | `rawFormatter` | `Uint8Array` of one complete MessagePack value |
| `sbyte[]`, `short[]`, `ushort[]`, `int[]`, `uint[]`, `long[]`, `ulong[]`, `float[]`, `double[]`, `char[]`, `Half[]` (ext 78, spec §10.5) | `int8ArrayFormatter`, `int16ArrayFormatter`, `uint16ArrayFormatter`, `int32ArrayFormatter`, `uint32ArrayFormatter`, `int64ArrayFormatter`, `uint64ArrayFormatter`, `float32ArrayFormatter`, `float64ArrayFormatter`, `charArrayFormatter`, `halfArrayFormatter` | the matching typed array (`char` → `Uint16Array`, `Half` → `Float32Array`) or null; writes accept any array-like |

**Half NaN sign and payload (known parity loss, [#274](https://github.com/Dtronix/NexNet/pull/274)).** JS has no binary16 type, so `Half` is a `number` and
`Half[]` (ext 78) is a `Float32Array`. A JS NaN has no sign or payload the runtime can rely on (engines may
canonicalize NaN bits), and `halfFromBits` returns the plain `NaN` for every binary16 NaN. A NaN from a .NET peer
therefore reads as `NaN` and is written back as the quiet NaN `0x7E00`: .NET's `Half.NaN` (`0xFE00`) loses its sign
bit, and any other payload is lost. Both are still NaN in .NET (`Half.IsNaN`), so only the bits differ; every other
half, -0 and the infinities included, round-trips bit for bit. This applies to `halfFormatter` and
`halfArrayFormatter` alike. The runtime's golden tests compare any NaN with any NaN (`tests/golden/README.md`,
"NaN"), and the generated test-scaffolding runner skips the vector `ext78.half` (which holds `0xFE00`) for this reason. An exact
round trip would need the raw bits (for example a `Uint16Array` for `Half[]`), which changes the formatter API
and is a contract change.

**Checked-number mapping ([#259](https://github.com/Dtronix/NexNet/pull/259)).** `long`/`ulong` are `bigint` by default. A member or assembly that opts in to the
checked `number` mapping uses `int64NumberFormatter` (±(2^53 − 1)) or `uint64NumberFormatter` (0 … 2^53 − 1). Writing
a value outside that range throws `RangeError`; reading one throws `NexusSerializationError` `range`. Nothing is ever
silently rounded.

**Combinators.** Each returns a new formatter; every container is one nesting level.

| Combinator | C# | JS value |
|---|---|---|
| `nullableFormatter(item)` | `T?` of a value type | `T \| null` |
| `arrayFormatter(item)` | `T[]`, `List<T>` and the list interfaces, `Queue<T>` (front first), `Stack<T>` (top first) of a non-primitive `T` | `T[] \| null`; writes accept any iterable |
| `setFormatter(item)` | `HashSet<T>` | `Set<T> \| null` (members compare by identity) |
| `mapFormatter(key, value)` | `Dictionary<K,V>` and the dictionary interfaces | `Map<K,V> \| null` (never a plain object; keys compare by identity, NEXNET046; a repeated key keeps the last value); writes accept a `Map` or an iterable of `[key, value]` |
| `tupleFormatter(...formatters)` | `ValueTuple<…>` | an array of exactly that many elements; a struct, so wrap it in `nullableFormatter` for `Tuple<…>` or `(A, B)?` |
| `keyValuePairFormatter(key, value)` | `KeyValuePair<K,V>` | `[key, value]` |

**`FormatterRegistry`** holds formatters by string key: `register(key, formatter)` (throws `TypeError` for a
non-string key or a value without `write`/`read`, and `Error` for a key already registered), `get(key)` (throws when
missing) and `tryGet(key)` (undefined when missing). Generated code registers user target formatters (`[NexusTargetFormatter<T>]` mappings) and generic
instantiations there.

**Guid helpers** (`src/values/guid.js`). A Guid is its lower-case "D" string. `EMPTY_GUID`; `parseGuid(text)`
normalizes the "D", "N" or "B" form in any case (`SyntaxError` otherwise); `guidToBytes`/`guidFromBytes` convert to and
from the 16 RFC 4122 (big-endian) bytes, which are the wire form (spec §10.6); `guidToDotNetBytes`/`guidFromDotNetBytes`
convert to and from the mixed-endian bytes of C# `Guid.ToByteArray()`, which are **not** the wire form.

The members listed above are frozen, including the ones marked (\*), which were added when the codec was implemented;
adding a member is not a contract change, renaming or removing one is.

### 3.3 Client (`client.js`, `config.js`, `transport.js`)

`NexusClient<TNexus, TProxy> extends EventTarget`:

- `static create(config, nexus, binding)` creates an instance of the class it is called on. `binding` is a
  `ClientBinding` (§4) that the generated `create<Export>Client(config, nexus)` supplies.
- `connect({signal})`, `tryConnect({signal})` → `ConnectionResult` (`success`, `state`, `disconnectReason`, `error`),
  `disconnect()`, `[Symbol.asyncDispose]()`. On a connected client `connect`/`tryConnect` succeed and do nothing (C#
  parity); during an attempt they share that attempt's result.
- `state` (`ConnectionState`), `proxy`, `isSecure`, `remoteCertificate`, `remoteAddress`, `remotePort`, `disconnected`
  (a promise, below), `reconnection` (below), `config`, `nexus`.
- `createPipe()`, `createChannel(formatter)`, `getSnapshot()`.
- Events (`CustomEvent`, dispatched from a microtask, never re-entrantly from a transport callback):
  - `statechange`, `detail: { state, previous }` (both `ConnectionState` values), on every change of `state`;
  - `disconnected`, `detail: { reason }` (a `DisconnectReason`), once per session that completed its handshake, just
    before the nexus's `onDisconnected(reason)` hook. A connect that fails before the handshake completes is reported
    only through the `connect`/`tryConnect` result, not through this event. That includes a reconnect attempt that
    fails: it dispatches `statechange` only.
- `disconnected` (the promise) resolves once the current session has ended and no reconnection will bring it back: at
  once when reconnection is off or the policy declines the reason, otherwise when the reconnection loop gives up
  (`reconnectfailed`) or `disconnect()` is called. A successful reconnect keeps the same promise. Awaiting it after
  the `disconnected` event sees the nexus's `onDisconnected` hook already called.
- `getSnapshot()` returns a `NexusSessionSnapshot` (§3.9), or null when the client has no session that completed its
  handshake.

**Reconnection.** `config.reconnectionPolicy` is a `ReconnectionPolicy`
`{ reconnectDelay(attempt): number | null, shouldReconnect?(reason): boolean }` (C# `IReconnectionPolicy`; attempt is
0-based, delays are milliseconds, null stops). When the property is absent, a browser client uses
`DefaultReconnectionPolicy` (0, 2, 10 and 30 s, then every 30 s; reasons `SocketError`, `Timeout` and
`ServerRestarting`) and a Node client uses none; `null` turns reconnection off. Without `shouldReconnect` a policy
reconnects for the default reasons. After the first successful connect, `client.reconnection` is the
`ReconnectController` (null before, and when reconnection is off). When a session that completed its handshake ends
with a reason the policy accepts, the controller calls `nexus.onReconnecting()`, waits each policy delay on the client
clock and retries with `ClientGreetingReconnection` (101); a successful attempt calls `nexus.onConnected(true)`. It
dispatches `CustomEvent`s: `reconnecting {reason}`, `reconnectattempt {attempt}` (1-based), `reconnected {attempts}`
and `reconnectfailed {reason, attempts}`. In a browser it also cuts a pending delay short on `visibilitychange` (to
visible), `online` and `resume`. `disconnect()` stops it for good.
- `static transports`: the transport factories the entry supports, keyed by transport kind. `NexusClient` (core and
  browser) has `webSocket`; `NodeNexusClient` adds `httpSocket`, `tcp`, `tcpTls` and `uds`.

`ClientConfig` is a plain object: exactly one transport property (`webSocket`, `httpSocket`, `tcp`, `tcpTls`, `uds`)
plus the common options, named as the C# `ClientConfig`/`ConfigBase` properties in camelCase, durations in
milliseconds. `authenticate({signal})` may return the token synchronously or as a promise. It runs before the transport
connects, on every connect and reconnect, bounded by the handshake timeout; if it throws, the connect fails with
`DisconnectReason.Authentication` and no connection is opened (as in C#, [#114](https://github.com/Dtronix/NexNet/pull/114)).

The optional `clock` property (C# `ConfigBase.Time`) is the time source of every client and session timer: the
connection, handshake and authenticate timeouts, the keepalive, and the idle and progress timeouts. The disconnect delay
and the wait for the disconnect byte run on real time whatever the clock (as C# and Java), so a fake clock never holds a
disconnect ([#291](https://github.com/Dtronix/NexNet/pull/291)).
It is a `Clock` (`src/session/clock.js`): `now()` in milliseconds on a monotonic clock, plus `setTimeout`,
`clearTimeout`, `setInterval` and `clearInterval` with opaque handles. The default, `systemClock`, is
`performance.now()` and the global timers. Tests inject a manual clock (`test/session/support/ManualClock.js`).

**Keepalive.** Only the client pings (spec §5.5). The interval is `pingInterval` when set, else a third of the
server's advertised `idleTimeoutMs`, else 10,000 ms. Each tick first checks the receive timeout (`timeout`) and
the progress timeout (`progressTimeout`, §9), then sends a `Ping`. In a browser, with the default clock, the keepalive
runs in a dedicated Worker created from a `blob:` URL, because main-thread timers in background tabs are throttled to
about once a minute or frozen, which would let the server's idle timeout expire. If no Worker can be created (no
`Worker`, or a Content-Security-Policy without `worker-src blob:`) it falls back to `setInterval`. Node has no global
`Worker` and always uses `setInterval`; an injected clock always uses `clock.setInterval`.

`isSecure` is true only for transports that declare themselves secure: TLS, WSS, HTTPS and (Node) UDS. Over any other
transport a client logs `NexNet: unencrypted transport (<transport>); credentials and data are visible on the network.`
once per instance, on the first connect. Plaintext stays allowed; the warning and `isSecure` make it visible.

The `Transport` interface between the session and the transports: `write(chunks)`, `onData(cb)`, `onClose(cb)`,
`close(reason)`, `isSecure`, `remoteCertificate`, `remoteAddress`, `remotePort`, `name`. A `TransportFactory` is `(config, {signal}) => Promise<Transport>`.
The Node TLS transports (`tcpTls`, `https:` HttpSocket, `wss:` WebSocket) set `remoteCertificate` to the server's
`X509Certificate` (`node:crypto`); every other transport, the browser WebSocket included, sets it to null. The session
exposes it as `session.remoteCertificate`, and `NexusClient.remoteCertificate` returns the current session's value:
null when not connected (before the first connect, after a disconnect, between reconnect attempts) and on non-TLS
transports. Its JSDoc type is `unknown` so the platform-neutral declarations do not depend on Node types.

`remoteAddress` (`string | null`) and `remotePort` (`number | null`) are the server's endpoint (C# `Context.RemoteAddress`/
`RemotePort`, Java `remoteAddress()`/`remotePort()`). Every Node transport sets them from its socket's peer
(`socket.remoteAddress`/`remotePort`); UDS reports the socket path and no port, as C# does. The browser WebSocket
cannot see the peer and leaves both null. The session exposes the transport's values, and `NexusClient` returns the
current session's: null when not connected. Unlike the C# client, whose WebSocket and HttpSocket transports report no
endpoint, the Node (and Java) WebSocket and HttpSocket transports report the socket's peer.

### 3.4 Generated-code base classes (`proxy.js`, `nexus.js`)

`ProxyBase` (base of `<Server>Proxy`); all members are protected:

| Member | C# method shape |
|---|---|
| `_invoke(methodId, args, {signal, returns})` → `Promise<T>` | `ValueTask` (no `returns`) and `ValueTask<T>` |
| `_invokeVoid(methodId, args)` → `void` | `void` (fire-and-forget; queued for credit, never dropped) |
| `_invokePipe(methodId, pipe, args, {signal})` → `Promise<void>` | `INexusDuplexPipe` parameter |
| `_invokeChannel(methodId, channel, args, {signal})` → `Promise<void>` | `INexusDuplexChannel<T>`/`INexusDuplexUnmanagedChannel<T>` parameter |
| `_collection(methodId, formatter, {mode, equals, valuesFormatter})` → `NexusList<T>` | collection property |

`args` is an `ArgumentsWriter` `(writer) => void` that writes **one MessagePack array** with an element per C#
parameter in declaration order, excluding the `CancellationToken`; `null` when there are no parameters. For pipe and
channel methods it is a `PipeArgumentsWriter` `(writer, pipeId) => void` that writes the pipe or channel parameter as
`pipeId` at its position.

`_collection` returns one `NexusList` per `methodId` for the lifetime of the client; it follows the client's current
session. Its options:

- `mode`: the `[NexusCollection]` mode of the server property, a `NexusCollectionMode` value (`Unset` 0,
  `ServerToClient` 1, `BiDirectional` 2, `Relay` 3; `src/collections/mode.js`). Default `ServerToClient`, as in C#.
  `Unset` and unknown values throw `TypeError`. Only `BiDirectional` accepts changes from a client; `Relay` behaves
  like `ServerToClient` for a client (protocol spec §12.2).
- `equals`: item equality for `remove(item)`, `indexOf` and `contains` (protocol spec §12.9). Default: see §3.5.
- `valuesFormatter`: the formatter of the C# `T[]`, which reads the values of a reset. Generated code passes it when
  C# writes `T[]` as ext 78 (arrays of primitive numeric types, protocol spec §10.5). Default: a MessagePack array of
  items read with `formatter`.

`ClientNexusBase<TProxy>` (base of `<Client>NexusBase`):

- hooks `onConnected(isReconnected)`, `onDisconnected(reason)` and `onReconnecting()`, no-ops by default, may be async;
- `context`: a `ClientContext` with `proxy`, `sessionId`, `isSecure`, `remoteAddress`, `remotePort`, `createPipe`,
  `createChannel` and `disconnect`;
- `_dispatch(methodId, reader, ctx)`: the generated override switches on `methodId`, reads the arguments array from
  `reader`, calls the method and reports a `ValueTask<T>` result with `ctx.writeResult(formatter, value)`. `ctx` is a
  `DispatchContext`: `invocationId`, `signal` (the C# `CancellationToken`), `writeResult`, `pipe(pipeId)` and
  `channel(pipeId, formatter)`. Unknown IDs fall through to `super._dispatch`, which throws. The runtime checks
  `methodId` against `acceptedIds` before dispatching.

  The generated `_dispatch` awaits every method, C# `void` methods included, so a failure (sync or async) reaches the
  runtime, which logs it. The invocation's execution slot is held until the method settles, so a `void` method that is
  still running counts against `maxConcurrentConnectionInvocations` (or `maxSeparatePoolInvocations`). This is a JavaScript
  design choice; the Java client nexus does not wait for `void` methods.
- `onInvocationException(error, methodId)` (C# `OnInvocationException`): called when a method that returns a result
  throws, before the failure is sent. Return a `NexusRemoteError` (`{ code?: number | null, message?: string | null }`)
  to send that in place of the exception's detail, whatever `remoteExceptionDetail` says; return null or undefined to
  send what that setting selects (type and message for `TypeAndMessage`, otherwise nothing). A `code` that is not an
  int32 is sent as null; the remote type is never sent with a returned error. Not called for canceled or
  fire-and-forget invocations. A throw from the hook is logged and treated as null.
- `_separatePool(methodId)` (protected): true for `[NexusMethod(SeparatePool = true)]` methods. Such invocations run in
  a second execution pool limited by `maxSeparatePoolInvocations`; all others share the pool limited by
  `maxConcurrentConnectionInvocations`. The base returns false; generated code overrides it only when the nexus has
  such methods.

### 3.5 Pipes, channels, collections, pool

- `NexusDuplexPipe`: `id`, `readable` (`ReadableStream<Uint8Array>`), `writable` (`WritableStream<Uint8Array>`), `ready`,
  `completed`, `complete()`, `[Symbol.asyncDispose]`.
- `NexusDuplexChannel<T>`: `pipe`, `getReader()`, `getWriter()`, `complete()`, `[Symbol.asyncDispose]`.
- `NexusChannelReader<T>`: `read()` → `IteratorResult<T>`, `readBatch(max)`, `readUntilComplete()`,
  `[Symbol.asyncIterator]`, `isComplete`. `NexusChannelWriter<T>`: `write`, `writeMany`, `complete`, `writeAndComplete`.
- `NexusList<T> extends EventTarget` (event `changed`): `state`, `isEnabled`, `ready`, `disabled`, `mode`, `version`,
  `count`, `length`, `get`, `at`, `indexOf`, `contains`, `toArray`, iterator, `enable`, `disable`, and the
  `Promise<boolean>` mutations `add`, `insert`, `remove`, `removeAt`, `replace`, `move` and `clear`.
  - `mode` is the `NexusCollectionMode` passed to `_collection`. `version` is the list version the replica is at
    (protocol spec §12.3).
  - `length` is `count`. `get(index)` throws `RangeError` when out of range (C# indexer); `at(index)` follows
    `Array.prototype.at`: a negative index counts back from the end, and out of range returns `undefined`.
  - `changed` is a `CustomEvent` whose `detail` is a `NexusListChange<T>`: `{ action, index?, item?, oldItem?,
    fromIndex?, toIndex? }`. `action` is `add`, `remove`, `replace` or `move` (C# `NexusCollectionChangedAction`),
    `reset` (a Clear, a completed reset, or the list closing; the list is then empty or holds the reset's items), or
    `ready` (follows the `reset` of every completed reset, the initial synchronization included, as C# raises
    `Ready`). `add` carries `index` and the new `item`; `remove` carries `index` and the removed `item`; `replace`
    carries `index`, the new `item` and `oldItem`; `move` carries `fromIndex`, `toIndex` and the moved `item`.
  - Default equality (C# `EqualityComparer<T>.Default` for the JS mappings): an item with an `equals` method (the
    runtime value types, generated structs and records) uses it; anything else compares with SameValueZero, which is
    `===` except that NaN equals NaN. Objects without `equals` compare by identity. Pass `equals` to `_collection` to
    override it.
  - Mutations are BiDirectional only and run one at a time, in call order. Each resolves with true once the server
    applied it and false when the server discarded it or the collection closed; the list changes only when the
    server's change arrives (no optimistic apply). A mutation made while `enable` runs, before the initial reset
    arrived, waits for that reset and is then built from the synchronized state and sent with its version; it
    resolves with false when the enable fails. Mutations reject with a `NexusError` in ServerToClient and Relay mode
    and when the list is not enabled, and with `RangeError` for an index that is not a non-negative int32.
- `NexusList.setProcessTestHook(hook)` is a test hook, not for applications (C# `NexusBroadcastClient.ProcessTestHook`;
  the interop host's `list.throttle` uses it). `hook` (`() => void | PromiseLike<void>`, or `null` to remove it) is
  called in the list's read loop before each received list message is processed. While the promise it returns is
  pending, the list neither processes nor reads anything more from its pipe, so it grants the server no pipe credit: a
  slow or stalled consumer. A hook that throws or rejects is logged at `debug` and ignored; a message already waiting
  for a removed hook still waits for its promise. A non-function other than `null` throws `TypeError`.
- Pipe details:
  - `writable` has a `highWaterMark` of **1** chunk, not 0: with 0, `ReadableStream.pipeTo` never writes (it waits for
    a positive `desiredSize`). The sink still takes one chunk at a time and sends only what the credit allows.
    `readable` is a byte stream with `highWaterMark` 0, so nothing is pulled, and no credit granted, before a read.
  - `forwardTo(destination, {signal})` copies what the pipe receives to `destination` and half-closes `destination`
    when the input completes (C# `ForwardToAsync`); it waits for the destination's credit before consuming, so a slow
    destination stalls the source's writer. `bridge(other, {signal})` / `NexusDuplexPipe.bridge(a, b, {signal})`
    forward both ways (C# `BridgeAsync`): each direction half-closes its destination; an abnormal end of either pipe
    completes both; a signal stops both directions without completing either and rejects with its reason.
  - A pipe from `createPipe()` holds a pipe slot and a receive window from the session budget until it is **disposed**
    (`[Symbol.asyncDispose]`, or `await using`), even if it was never passed to a method. A pipe the server refused
    frees itself. A pipe a client nexus method received is released when the method returns.
- `NexusClientPool<TNexus, TProxy>`: `new NexusClientPool(config, nexusFactory, binding)`, `maxConnections`,
  `availableConnections`, `rent({signal})` → `RentedNexusClient`, `collectionConnector(selector)`,
  `[Symbol.asyncDispose]`.

### 3.6 Errors, cancellation and enums

| Error | Raised when |
|---|---|
| `NexusError` | Base class |
| `NexusTransportError` (`reason`) | Transport failure (for example, not connected). For an invocation pending when the session ends it is the `cause` of an `AbortError` (below) |
| `NexusRemoteInvocationError` (`code`, `remoteType`, `remoteMessage`) | The remote method threw |
| `NexusUnauthorizedError` | The server rejected the call as unauthorized |
| `NexusBusyError` | A pipe, channel or large-message limit refused the operation |
| `NexusMessageTooLargeError` | A message exceeded the negotiated `MaxMessageSize` |

Cancellation (a call canceled before it is sent rejects and sends nothing; it never resolves with a default value) is not a NexNet error class: operations reject with `cancellationError(signal)`, which is
`signal.reason` when set and otherwise a `DOMException` named `AbortError`. `isCancellationError(e)` is true for
`AbortError` and `TimeoutError`.

**Session end ([#158](https://github.com/Dtronix/NexNet/pull/158), [#160](https://github.com/Dtronix/NexNet/pull/160)).** An invocation still pending when the session ends (waiting for credit, streaming,
or waiting for its result) completes as canceled, as in C# (`TaskCanceledException`) and protocol spec §4.5: it
rejects with a `DOMException` named `AbortError` whose `cause` is a `NexusTransportError` carrying the disconnect
`reason`. A call made while not connected still rejects with `NexusTransportError` directly.
`cause` is set as an own, non-enumerable property, because not every platform's `DOMException` constructor accepts a
`cause` option; read it as `error.cause`. When the session ends, server-to-client invocations that are queued are
dropped and those running see `ctx.signal` abort.

`ConnectionState`, `ConnectionResultState`, `DisconnectReason` (wire codes 20–38), `RemoteExceptionDetail`,
`NexusCollectionState`, `NexusCollectionMode` and `DateTimeKind` are frozen objects with the C# values.

### 3.7 Transport errors and TLS

A transport factory rejects a failed connect with a `NexusTransportError` carrying two extra fields
(`TransportConnectError` in `src/transport/TransportBase.js`):

- `transportError`: the C# `TransportError` name (protocol spec §13.1): `InternalError`, `ConnectionAborted`,
  `AddressInUse`, `InvalidAddress`, `ConnectionTimeout`, `Unreachable`, `ConnectionRefused`, `ProtocolError`,
  `ConnectionReset` or `AuthenticationError`;
- `status`: the HTTP status of a refused upgrade (HttpSocket and Node WebSocket only); absent otherwise.

`reason` is `DisconnectReason.Authentication` for `AuthenticationError` and `SocketError` for everything else, as in
the C# client. `connect()` rethrows this error as is; `tryConnect()` returns it as `error` with that
`disconnectReason`. A connect that exceeds `connectionTimeout` fails with `DisconnectReason.Timeout` instead.

**Authentication failures during the handshake ([#299](https://github.com/Dtronix/NexNet/pull/299)).** `connect()` also rejects with a `NexusTransportError` whose
`transportError` is `AuthenticationError` (and `reason` `DisconnectReason.Authentication`), as C# `ConnectAsync`
throws `TransportException(AuthenticationError)`, in two cases:

- the server ends the handshake with `DisconnectReason.Authentication` (it refused the greeting token). The error
  message is `Authentication failed.`; `tryConnect()` reports this case as `state` `Disconnected` with
  `disconnectReason` `Authentication` and no `error`;
- `authenticate` does not settle within `handshakeTimeout`. `tryConnect()` returns `state` `Exception` with that error.

A handshake the server ends for any other reason rejects with a `NexusTransportError` carrying that `reason` and no
`transportError`.

| Failure | `transportError` | `reason` |
|---|---|---|
| Node socket error `ECONNREFUSED`, `ENOENT` (UDS path) | `ConnectionRefused` | `SocketError` |
| `ENOTFOUND`, `EAI_AGAIN`, `ENETUNREACH`, `EHOSTUNREACH` | `Unreachable` | `SocketError` |
| `ECONNRESET`, `EPIPE` | `ConnectionReset` | `SocketError` |
| `ECONNABORTED` | `ConnectionAborted` | `SocketError` |
| `ETIMEDOUT` | `ConnectionTimeout` | `SocketError` |
| `EADDRINUSE` | `AddressInUse` | `SocketError` |
| `EADDRNOTAVAIL`, `EINVAL` | `InvalidAddress` | `SocketError` |
| Any error after the TCP connect and before the TLS handshake completes, or a TLS/certificate error code | `AuthenticationError` | `Authentication` |
| Upgrade refused with `401` or `403` (HttpSocket, Node WebSocket) | `AuthenticationError`, `status` set | `Authentication` |
| HttpSocket upgrade refused with any other status, `2xx` included | `InternalError`, `status` set | `SocketError` |
| Node WebSocket upgrade refused with `5xx` | `InternalError`, `status` set | `SocketError` |
| Node WebSocket upgrade refused with any other status | `ProtocolError`, `status` set | `SocketError` |
| `101` with a wrong `Upgrade`/`Connection`/`Sec-WebSocket-Accept`, or a subprotocol or extension selected | `ProtocolError` | `SocketError` |
| Browser WebSocket: any connect failure, an upgrade refused with `403` (NexNet.Asp `AllowedOrigins`) included (the platform hides the cause and the status) | `InternalError` | `SocketError` |
| Any other error | `InternalError` | `SocketError` |

After the connection is up, the error a transport ends with is only logged (at `debug`): the session ends with
`DisconnectReason.SocketError`, or `SocketClosedWhenWriting` when a write failed. The TCP, TLS, UDS and HttpSocket
transports report the Node socket error, or none for a plain end. The WebSocket transports report `ConnectionAborted`
for a close other than code 1000 (or a connection lost without a Close frame, 1006) and `ProtocolError` for an RFC 6455
violation or a text message. A write on an ended transport rejects with `ConnectionAborted`.

**Credentials.** The greeting token (`authenticate`) is the canonical credential for every transport, because browsers cannot set an `Authorization` header on a WebSocket. For the
HTTP-based transports in Node, extra upgrade headers, an `Authorization` header for example, go in
`config.webSocket.headers` or `config.httpSocket.headers`; the transport sets its own upgrade headers (`Connection`,
`Upgrade` and, for WebSocket, `Sec-WebSocket-Version` and `Sec-WebSocket-Key`) after them. Browsers
cannot send custom headers on a WebSocket, so a token for a NexNet.Asp query-string hook ([#110](https://github.com/Dtronix/NexNet/pull/110)) goes in
`config.webSocket.queryToken` or `config.httpSocket.queryToken` (`{ name, value }`, Java `ClientConfig.Builder.queryToken`),
in Node as well as in browsers. The transport appends `name=value`, each URL-encoded with `encodeURIComponent`, to
the URL's query, after any query the URL already has; transport error messages show the configured URL without it.
The name must be a non-empty string and the value a string (`TypeError` otherwise). Putting the token in the URL
yourself still works, but the token then shows in error messages.

**Refused authentication in browsers.** The platform `WebSocket` fails a refused upgrade the same way as an
unreachable server or a TLS failure (close code 1006, no status, no reason). NexNet.Asp therefore does not refuse a
WebSocket upgrade that fails ASP.NET authentication (the `Authorization` header, a cookie or the query-string token):
it accepts the WebSocket, sends its preamble, and answers the greeting with `DisconnectReason.Authentication`, as it
does for a refused greeting token. `connect()` rejects with `transportError` `AuthenticationError` in browsers, as
in Node, Java and C#, and the interop suite expects that on every row of `AspClientServerTests`. Only an `Origin`
outside `AllowedOrigins` is still refused at the upgrade (`403`), which a browser reports as `InternalError`.

**TLS options and pinning (Node).** `TlsOptions` follow `tls.connect`. Unless `rejectUnauthorized` is false, the
chain must lead to a trusted CA (`ca`, else Node's bundled roots) and the host name is verified with
`tls.checkServerIdentity` (against `servername`, defaulting to the URL or `host` name).

**Pins.** `pins` is the built-in pin list, with the same semantics as Java `TlsOptions.Builder.pinCertificateSha256`. Each pin is a SHA-256 value, as base64 text (base64url and missing padding are accepted) or as 32 raw bytes
(`Uint8Array`). A pin matches a server chain certificate when it equals either form:

- certificate SHA-256: the SHA-256 of the certificate's DER encoding;
- SPKI SHA-256: the SHA-256 of its DER `SubjectPublicKeyInfo` (the HPKP `pin-sha256` value), which survives a
  renewal with the same key.

The connect succeeds only when some pin matches some certificate of the chain: the leaf, the intermediates the server
sent and, when Node can find it (`ca` or the bundled roots), the root. The transports check the pins themselves after
the handshake (`socket.getPeerCertificate(true)`), so they apply **in addition to** CA trust when
`rejectUnauthorized` is true and **on their own** when it is false (pinning a self-signed server without a `ca`).
A mismatch fails the connect with `AuthenticationError` (`DisconnectReason.Authentication`). Over `https:` HttpSocket
and `wss:` WebSocket the upgrade request is held until the pins are checked, so no header (an `Authorization` header,
say) reaches a server that fails them. A malformed pin (not base64, not 32 bytes) rejects the connect with a
`TypeError`. An empty or absent list means no pinning.

```js
const tls = { ca: testCaPem, pins: ['MZEa+vKvxw+5EI8S4C6W811NN39NrGjkKDakkDBwHdE='] }; // server SPKI SHA-256
```

A user `checkServerIdentity(hostname, certificate)` is still accepted for other checks. It runs after the host-name
check passes, and returning an `Error` fails the connect with `AuthenticationError`. Node calls it only when chain
validation succeeded and honors its result only when `rejectUnauthorized` is true, so it cannot replace `pins`.

Browsers do the TLS themselves and ignore `tls`: no custom CA, client certificate or pinning (capability skips).

### 3.8 Runtime internals: session extension points

The layers above the session core (invocations, pipes, collections, reconnection) plug into
`NexusSession` (`src/session/NexusSession.js`) through these members. They are internal to the runtime: not exported
from the package entries, and generated code never uses them. The client creates one session per connect attempt and
attaches the layers (`#attachSessionLayers`) **before** `start()`, so frames that arrive in the same read as the
`ServerGreeting` find their handlers.

| Member | Contract |
|---|---|
| `setHandler(type, handler)` | Registers the `FrameHandler` of a message type received after the handshake. A received type without a handler is a protocol error (`ProtocolError`). `Ping`, `ServerGreeting`, `ClientGreeting` and `ClientGreetingReconnection` belong to the session: registering them throws `TypeError`. A later registration for the same type replaces the earlier one |
| `send(frame)` | Queues one encoded frame. Resolves true once the transport took it, false when the session ended first or the handshake has not completed (nothing is sent then). Frames queued in the same tick go out in one transport write |
| `controlSender` | The `ControlSender` (C# `SessionControlSender`). Its requests (`requestPong`, `requestPipeControl(source)`, `requestAbort(id, kind, reason)`, `requestInvocationCancellation(id)`, `returnInvocationCredit(n)`) only record what is owed; frames are built when the write queue flushes, so repeated requests cost at most one frame each, and credit is batched to half the advertised `invocationCredits`. A `PipeControlSource` implements `takePendingControl(): Uint8Array[]`. Everything pending is dropped when the session ends |
| `onClose(listener)` | `listener(reason)` runs once, synchronously, when the session reaches `Disconnected`, after the transport closed and before `closed` resolves. A throwing listener is logged; the others still run |
| `addProgressProbe(probe)` | `probe(now, progressTimeout)` runs on every keepalive tick (§9) after the session's own write-stall check. Return a description of what stalled, or null; the first non-null result ends the session with `DisconnectReason.Stalled` |
| `addSnapshotSource(source)` | `source.pipes?(now)` and `source.largeMessages?(now)` return the layer's `NexusPipeSnapshot`s and `NexusLargeMessageSnapshot`s; `pipeSnapshots(now)` and `largeMessageSnapshots(now)` concatenate them. The pipe layer and the invocation layer register theirs when they attach |
| `snapshot(now)` | The session part of `NexusSessionSnapshot`: `connected` (ms since the transport connected, `connectedAt`), `sinceLastSent` (null until a write completed) and `flushInProgress` (null when no transport write is in flight) |
| `addMetricsSink(sink)` / `recordMetric(name, value, tags)` | Event-instrument hook. A layer calls `recordMetric` with an `Instruments` key, the increment or histogram value (seconds for durations) and the tags beyond role and transport; it costs one empty-array loop when no sink is attached. `addMetricsSink` returns a detach function; sinks are dropped when the session reaches `Disconnected`. Sinks run synchronously and must not throw |

A `FrameHandler` receives a `Frame` (`type`, `body`, and the post-header fields `pipeId`, `invocationId`, `kind`) and
returns a disconnect reason to end the session (the disconnect byte is sent) or nothing / 0 to continue. A throw ends
the session with `ProtocolError`. Handlers run synchronously in the transport's data callback and must not call user
code from there; defer it to a microtask.

**Body lifetime.** `frame.body` is a view into the frame reader's buffer, which is reused and compacted by later
reads. It is valid only until the handler returns: copy (`body.slice()`) anything that must outlive the call, such as
a pipe payload queued for a reader or a large-message chunk.

`addSessionObserver({ started(session) })` (`src/session/observers.js`) registers a process-wide observer that
`start()` calls synchronously, before the session reads from its transport. The metrics layer uses it to count a
tracked client's sessions from the transport connection, the handshake included.

Other session members the layers read: `ready` and `closed` (promises that never reject), `id`,
`isHandshakeComplete`, `isDisconnecting`, `disconnectReason`, `options` (the resolved `ClientConfig`),
`peerMaxMessageSize`, `peerInvocationCredits`, `sendMaxMessageSize`, `idleTimeoutMs`, `pingInterval` and the
frame/byte counters used by `getSnapshot()`.

**Invocation codec.** The invocation layer gets its writers and readers from a process-wide factory in
`src/invocation/codec.js`: `invocationCodec()` returns `{ createWriter(), createReader(bytes, serializerOptions) }`,
by default `new MsgPackWriter()` and `new MsgPackReader(bytes, options)`. `DispatchContext.writeResult` and the reader
passed to `_dispatch` come from it. `setInvocationCodec(codec)` replaces it (null restores the default) and returns the
previous one; only tests use it. Generated code
never does.

### 3.9 Diagnostics: leak-audit counters and snapshots

The `diagnostics` namespace (`src/diagnostics/`) is what the leak audit of the interop harness reads:

- `diagnostics.counters()` → `{ sessions, pipes, timers, pendingInvocations, subscriptions, detail }`, the process-wide
  totals: `sessions` is `openSessions`; `pipes` is the pipe layer's `openPipes`; `timers` adds the session timers and
  the ops timers (reconnect delays, pool health checks); `pendingInvocations` adds outbound calls and server-to-client
  invocations; `subscriptions` counts event listeners the runtime holds (reconnection, browser lifecycle, a
  `NexusMetrics` with tracked clients). `detail` holds the per-layer sets below and the ops set
  (`getOpsCounters()`: `timers`, `subscriptions`, `pooledClients`).
- `diagnostics.isIdle(c?)` is true when every total and every `detail` counter is zero: after every client has
  disconnected and every pool and tracking `NexusMetrics` is disposed.
- `diagnostics.registerCounterSource(() => ({ pipes?, timers?, subscriptions? }))` adds another component's counters to
  the totals; it returns an unregister function.
- `diagnostics.getSessionCounters()`, `getInvocationCounters()` and `getPipeCounters()` return the per-layer sets.

Each getter returns a snapshot copy. The per-layer counters live in `src/session/diagnostics.js`,
`src/invocation/diagnostics.js` and `src/pipes/diagnostics.js`.

The session and invocation counter sets are also exported, without the rest of the namespace, on the
`@dtronix/nexnet/diagnostics` subpath (`src/diagnostics.js`, platform-neutral), together with the `SessionCounters` and `InvocationCounters` typedefs:

```js
import { getSessionCounters, getInvocationCounters } from '@dtronix/nexnet/diagnostics';
```

The counters are process-wide (per module instance), so an audit must run when no other client in the process is
active. The main entries expose them only through the `diagnostics` namespace.

| Function | Counter | Counts |
|---|---|---|
| `getSessionCounters()` | `openSessions` | Sessions created and not yet `Disconnected` |
| | `timers` | Session timers running: handshake timeout, keepalive, disconnect delay, disconnect-write timeout |
| | `pendingWrites` | Frames queued or being written and not yet flushed |
| `getInvocationCounters()` | `pendingInvocations` | Outbound calls not yet completed (waiting for credit, sending, or waiting for their result) |
| | `reservedInvocationIds` | Outbound invocation IDs reserved (awaiting a result, or a late result after a cancel) |
| | `creditWaiters` | Outbound calls parked waiting for invocation credit |
| | `inboundInvocations` | Server-to-client invocations queued or running |
| | `largeMessages` | Large messages being sent or received |
| `getPipeCounters()` | `openPipes` | Pipes holding a receive window: created, open, or closing until both sides confirmed |
| | `bufferedBytes` | Received pipe bytes buffered and not yet read |

**Snapshots.** `client.getSnapshot()` (`getClientSnapshot`) returns the C# `NexusSessionSnapshot` with its
`NexusBudgetSnapshot`, `NexusInvocationSnapshot`, `NexusPipeSnapshot`, `NexusPartialItemSnapshot` and
`NexusLargeMessageSnapshot` parts, field names camelCased in C# declaration order (`SnapshotFields`, checked against
`tests/golden/snapshot-fields.json`). Durations are milliseconds on the client clock; `direction` and `kind` are
`'inbound'`/`'outbound'` and `'argument'`/`'result'`. Every field is filled from the session
(`snapshot()`), invocation (`invocationManager.snapshot()`) and pipe layers; a field is null only where C# is null:
`endpoint` (client), `sinceLastSent`, `flushInProgress`, `oldestQueuedWait`, `separatePoolOldestQueuedWait`,
`closing`, `sinceLastData`, `partialItem` and `waitingForCredit` when what they time has not started. `creditDrops` is
always 0 on a client: only a server's multi-session invocations drop calls for lack of credit.

**Awaiting results and reserved IDs.** `invocations.awaitingResults` counts the sent result calls that are not
completed yet, as in C# and Java. A call canceled after send completes at once, so it leaves that count, but its
invocation ID stays reserved until the peer's late reply arrives and is consumed (§4.5 of the protocol
specification). `diagnostics.getReservedInvocationIds(client)` (`getReservedInvocationIds` in
`src/diagnostics/snapshot.js`; `InvocationManager.reservedIdCount`) counts the IDs the client's current session
holds: result calls awaiting their result, calls canceled after send still awaiting their reply, and streamed
IgnoreReturn arguments still being sent. It is 0 when the client has no session. The interop host reports it as
`client.outstanding`, so a runtime that never releases a canceled call's ID fails the release checks.

### 3.10 Metrics

`NexusMetrics` (`src/metrics/`) reports the C# instruments of `docs/articles/metrics.md` with identical names, units,
kinds and tags. `Instruments` describes each one (`name`, `kind`, `unit`, `description`, extra `tags`, `serverOnly`,
advised histogram `buckets`); `METER_NAME` is `NexNet`. `NexusMetrics.shared` is a process-wide instance.

- `track(client)` / `untrack(client)` / `dispose()`. A tracked client's sessions are counted from the transport
  connection to the disconnect, the handshake included (`addSessionObserver`, §3.8). A session already open when
  tracking starts is counted from then on; its duration still runs from its transport connection.
- `addListener({ add?, record? })` receives the event instruments as they happen: `add(instrument, value, tags)` for
  counters, `record(instrument, value, tags)` for histograms. Listeners run synchronously where the event happens,
  possibly in the transport's data callback: keep them cheap. A throwing listener is ignored.
- `collect(observe)` reads the observable instruments (`observe(instrument, value, tags)`, once per instrument and tag
  set) from the live sessions, as the C# observable instruments do; the send and receive paths pay nothing.

| Instrument | Where the JS runtime records it |
|---|---|
| `nexnet.session.duration`, `nexnet.session.disconnects` | When a tracked session ends, duration first; `nexnet.session.phase` is `handshake` for a session that ended before the handshake completed |
| `nexnet.invocation.queue_wait` | When a server-to-client invocation takes an execution slot, tagged with its pool |
| `nexnet.pipe.credit_wait` | When a pipe writer's wait for credit ends (granted, completed or aborted) |
| `nexnet.pipe.resets` | When a channel item breaks the framing or does not decode (`invalid_item`) or exceeds `maxMessageSize` (`too_large`) |
| `nexnet.pipe.refusals` | `local` when `createPipe()` or a server-opened pipe hits `maxPipes` or the budget; `remote` when the server refuses an open |
| `nexnet.large_message.aborts` | Inbound `busy` (no budget) and `cancelled` (by the server); outbound `busy`/`too_large` (refused by the server) and `cancelled` (by the caller's signal) |
| Observable: `session.active`/`handshaking`, `io.frames`/`bytes`, `budget.reserved`/`limit`, `pipe.open`/`window`, `invocation.queued`/`executing` (per pool), `invocation.credit_waits`, `large_message.in_flight` (per direction) | `collect` |
| `nexnet.connection.rejections`, `nexnet.invocation.busy` | Never: server only |
| `nexnet.invocation.credit_drops` | Never on a client (see `creditDrops` above) |

Bridging to OpenTelemetry (`@opentelemetry/api` is not a dependency): create one OTel instrument per `Instruments`
entry with its name, unit and description (the histogram `buckets` as `advice.explicitBucketBoundaries`), forward
`add`/`record` from a listener, and call `collect` from a batch observable callback. The module comment of
`src/metrics/NexusMetrics.js` has the complete snippet.
