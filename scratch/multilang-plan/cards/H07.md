# H07 — NexNet.InteropServer multi-endpoint test server

| Size | Lands on | Requires | Unblocks | Branch |
|---|---|---|---|---|
| S | train | S02 | H05 | `mt/H07-interop-server` |

## Owns
- `src/NexNet.InteropServer/` (new): a library, plus an optional console entry point for manual debugging
- `src/NexNet.slnx` (**hot**)

## Steps
1. **`InteropServerHost.StartAsync(InteropServerOptions)`.** Starts **one** server using the multi-endpoint API (S02) with the interop server nexus from H02.
2. **Endpoints.** It exposes all of these at once:
   - TCP and TcpTls;
   - UDS;
   - HttpSocket over HTTP and HTTPS (Kestrel);
   - WS and WSS (Kestrel).

   Ports are bound on 0. TLS uses the F08 certificates.
3. **Options and result.** Options control the auth token validation, per-endpoint timeouts, and `AllowedOrigins` (`*` for the browser host). The result returns the URLs for each endpoint.
4. **Shared host mode.** For per-test isolation, the server can host multiple independent nexus servers routed by path `/t/{testId}/…`. This avoids a Kestrel start per test, which costs 50–150 ms. Tests that need restarts or refused connections get a dedicated instance.
5. **Self-test.** A C# self-test connects the in-proc client over every endpoint and asserts `Context.Endpoint`.
