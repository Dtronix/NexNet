## Steps
1. **Bundle source.** When the IR has any export with targets, and every target has its output configured, `AddSource("NexNet.Targets.g.cs")` with comment-only content:

   ```
   // <auto-generated/> NexNet target bundle v1
   // @file java/com/acme/ChatServerProxy.java sha256=<hex>
   // <base64 lines…>
   // @file nexnet-ir.json sha256=<hex>
   ```

   Paths are relative to each target's root, and the first segment is the target ID. Emit files via each `ITargetLanguage.Emit`, which is still empty until J03/K03; `nexnet-ir.json` is always included.
2. **MSBuild properties.** In the `.props`, the shorthand properties `NexNetJavaOutputDir`, `NexNetJavaPackage`, `NexNetJavaScriptOutputDir` and `NexNetJavaScriptModuleName` are converted into `<NexNetTarget Include="java" OutputDir=… Package=…/>` items. A target running `BeforeTargets="GenerateMSBuildEditorConfigFileCore"` flattens the items into the `CompilerVisibleProperty` values `NexNetTargets` and `NexNetTarget_<id>_<Option>`, excluding `OutputDir`.
3. **Unpack target.** In the `.targets`, only when `@(NexNetTarget)` is non-empty:
   - Before CoreCompile, set `EmitCompilerGeneratedFiles=true`. It must be set inside a target.
   - After CoreCompile, an inline `RoslynCodeTaskFactory` task, with Inputs = bundle and Outputs = stamp:
     - reads `$(CompilerGeneratedFilesOutputPath)/NexNet.Generator/NexNet.Generator.NexusGenerator/NexNet.Targets.g.cs`;
     - verifies the sha256 of each file;
     - writes only changed files to each target's `OutputDir`, atomically;
     - deletes files listed in the previous manifest (`obj/nexnet-targets.manifest`) that are no longer emitted;
     - hooks into `Clean`.
   - For multi-TFM projects, unpack only in the first TFM.
4. **Design-time builds.** Read `build_property.DesignTimeBuild`. In design-time builds, skip bundle emission but still validate.
5. **Isolation (D27).** With no `NexNetTarget` configured, nothing changes: no bundle, no `EmitCompilerGeneratedFiles`.
6. **Tests:**
   - unit: bundle format round-trip;
   - integration (real `dotnet build` of the sample project): files appear, an incremental rebuild leaves them untouched (timestamps unchanged), a removed export deletes its file, `dotnet clean` removes everything, and determinism holds (build twice, identical bytes).
