# F03 — Pre-send cancellation throws TaskCanceledException

## Problem (verified)
In `src/NexNet/Invocation/SessionInvocationStateManager.cs:122-126`, a token that is already canceled before send calls `state.TrySetNoResult()`. The credit-wait cancel path at line 180 does the same.

`src/NexNet/Internals/RegisteredInvocationState.cs` then:
- returns silently for `ValueTask` (line 280);
- returns `default!` for `ValueTask<T>` (line 346).

## Steps
1. Make pre-send cancellation complete the state as **canceled**. This covers both a token already canceled and a token canceled while awaiting credit.
   - Both `ValueTask` and `ValueTask<T>` then throw `TaskCanceledException`.
   - If `IsNoResult` or `TrySetNoResult` becomes unused, delete it.
2. Keep two existing guarantees: the invocation ID is not leaked, and nothing is sent. Existing tests assert both; keep them passing.
3. Add tests:
   - `ValueTask<int>` throws when the token is already canceled;
   - `ValueTask` throws when the token is already canceled;
   - a cancel during the credit wait throws;
   - fire-and-forget `void` methods are unaffected.
4. Update the docs and add a release note that starts "Behavior change:".
