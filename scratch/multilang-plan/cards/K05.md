# K05 — Java session core (reader/writer threads, executors)

| Size | Lands on | Requires | Unblocks | Branch |
|---|---|---|---|---|
| L | train | K01 | K06, K07 | `mt/K05-java-session` |

Mirror J05. Below are the Java-specific requirements.

## Owns
- `clients/java/nexnet-client/src/main/java/com/dtronix/nexnet/session/**`
- `.../transport/Transport.java` (the interface only)
- `.../client/NexusClient.java`
- tests (loopback transport plus golden frames)

## Steps
1. **Transport interface:** `InputStream`/`OutputStream`-style blocking IO, with `isSecure()`, `remoteCertificate()` and `close(reason)`.
2. **Threads.** Per connection: **one reader thread** (blocking read, then synchronous frame parse and dispatch) and **one writer thread** draining a bounded frame queue. A write never holds the session lock during socket IO.
3. **Completions.** **Every user-visible future completes via an executor.** Never call `complete()` on the reader thread. The default executor is a shared daemon pool; it is configurable, with an optional `callbackExecutor` (e.g. the Android main thread).
4. **No caller-thread IO.** `connect()` hops to the runtime executor immediately; there is never IO on the caller thread (`NetworkOnMainThreadException`).
5. **Session behavior.** Same as J05:
   - handshake;
   - limits;
   - disconnect handling;
   - control sender;
   - timers on a `ScheduledExecutorService` using `System.nanoTime`, with an **injectable clock**;
   - ping interval from `idleTimeoutMs`;
   - plaintext warning (D7);
   - diagnostic counters.
6. **Thread names.** `nexnet-<id>-reader` and `nexnet-<id>-writer`, as daemon threads. Close joins them with a timeout.

## Verify
`gradlew check`. Tests include a deadlock guard: user code blocking inside `thenApply` must not stall the reader.
