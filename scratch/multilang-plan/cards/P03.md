# P03 — Lockstep release pipeline (NuGet + npm + Maven Central)

| Size | Lands on | Requires | Branch | Decisions |
|---|---|---|---|---|

## Prerequisites (owner action; F01 documents them)
- npm org `@dtronix`, with an automation token stored as the `NPM_TOKEN` secret.
- Sonatype Central Portal account, with the `com.dtronix` namespace verified by DNS TXT on dtronix.com.
- GPG key in the secrets `SIGNING_KEY` and `SIGNING_PASSWORD`, plus `CENTRAL_USERNAME` and `CENTRAL_PASSWORD`.

## Owns
- `.github/workflows/release.yml` (**hot**)
- `llm-release.md` (**hot**)
- `clients/java/build-logic` (publishing: `maven-publish` + `signing`, plus a Central Portal plugin)
- `clients/js/packages/nexnet/package.json` (**hot**): `publishConfig`, `files`

## Steps
1. **Single version source.** The version comes from `src/NexNet.props` `<Version>`. A script stamps it into `packages/nexnet/package.json`; Gradle reads it directly. The release fails if the versions differ.
2. **Release workflow,** triggered on a `v*` tag:
   - run the full gate, including interop;
   - pack NuGet;
   - `npm publish --access public --provenance`;
   - `gradlew publishToCentral` (signed): core, `-kotlin`, `-okhttp` and `-micrometer`. `-android` is built and published from the Android-enabled job.
3. **Docs.** Update `llm-release.md` with the lockstep steps and a pre-1.0 note: server and clients upgrade together (D18).
4. **Dry run.** Add a `--dry-run` mode: npm `--dry-run`, and Gradle publish to a local repo.
