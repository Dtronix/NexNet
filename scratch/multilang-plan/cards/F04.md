# F04 — Unauthorized pipe/channel method sends Refused

| Size | Lands on | Requires | Branch |
|---|---|---|---|
| S | **master** | — | `mt/F04-unauth-pipe-refused` |

## Problem
`MethodEmitter.EmitNexusInvocation` in `src/NexNet.Generator/Emission/MethodEmitter.cs` returns on an unauthorized result before it registers the pipe. Nothing is sent back, so the opener's `ReadyTask` hangs until the session disconnects.

## Owns
- `src/NexNet.Generator/Emission/MethodEmitter.cs`
- `src/NexNet/Pipes/NexusPipeManager.cs` (only if a helper is needed)
- `src/NexNet/Invocation/NexusBase.cs` (only if needed)
- `src/NexNet.IntegrationTests/NexusServerTests_Authorization.cs`
- generator snapshot updates
- release notes

## Steps
1. When a pipe, channel or collection-connect method gets an Unauthorized result, send `DuplexPipeUpdateState[Refused]` for the opener's partial pipe ID, then return. Use the same path as a busy refusal. On a Disconnect result, keep the existing disconnect.
2. Decide what the client observes:
   - Prefer: a refused pipe fails `ReadyTask` with `NexusBusyException`.
   - If the authorization reason can be told apart **without a new wire state**, surface `ProxyUnauthorizedException` instead.
   - Do not add wire states. Document the outcome either way.
3. Add tests: a pipe method and a channel method under a denying `[NexusAuthorize]`. The client must observe the failure within 1 s, with no hang, and the session must stay up.

## Acceptance
- No hang.
- The outcome is documented in the release notes and `docs/articles/authorization.md`.
- The C# gate is green.
