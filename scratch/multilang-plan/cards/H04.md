## Supporting types
- **`ClientSpec`:**
  - transport and URL;
  - TLS: CA PEM, client certificate, SPKI pin, insecure flag;
  - timeouts, reconnect delays and ping interval;
  - auth token or header;
  - MaxMessageSize and InvocationCredits;
  - fakeTime;
  - logging.
- **`ErrorKind`:** Transport{reason}, RemoteInvocation{type, message, code}, Unauthorized, Canceled, Disconnected, Serialization, Busy, TooLarge, InvalidOperation. Each maps to the existing C# exception types.
- **`IRemotePipe`:**
  - Ready, Completed;
  - Write, WritePattern(seed, len), Read(min, max), Drain() → (len, sha256);
  - Complete;
  - ChannelWriter/Reader<T>.
- **`IRemoteList<T>`:** async CRUD, SnapshotAsync, WaitForAsync(predicate).
- **`ClientCapabilities`:** flags such as AuthorizationHeader, ClientCertificate, Pinning, CustomCa, RemoteCertificate, HttpSocket, Tcp, Uds, Quic, FakeTime and ClientPool.

## Steps
1. **Script interpreter (C#).** Steps:
   - Returns, Throws, Delay, AwaitSignal, AwaitCancel, Invoke;
   - Named(handler);
   - Forward (a C# lambda).

   The in-proc driver runs the **same** interpreter over the generated C# client nexus delegates (`ClientNexus` events). This keeps the semantics identical across languages (gotcha 12).
2. **`InProcClientDriver`.** Wraps `NexusClient`.
3. **Matrix data source.** `[ClientMatrix(Transports = …, Requires = Capability.X)]` is a TUnit data-source generator over `NEXNET_TEST_LANGS`.
   - Default: the `csharp` row only (D27).
   - Remote languages default to `HttpSocketTls` and `WebSocketTls`.
   - A row whose language lacks a required capability becomes a visible skip.
4. **Errors.** Rethrow mapping for the error kinds.
5. **Proof.** Port 3 sample tests (one invocation, one pipe, one collection) to `IClientUnderTest` and run them on the C# row.

## Verify
The full C# gate. With `NEXNET_TEST_LANGS` unset, only `csharp` rows appear.
