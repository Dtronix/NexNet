# S01 — Server lifecycle fixes + internal endpoint refactor

| Size | Lands on | Requires | Unblocks | Branch |
|---|---|---|---|---|
| M | train | — | S02 | `mt/S01-server-lifecycle` |

## Goal
Fix the verified lifecycle bugs and restructure `NexusServer` internally around a list of endpoints. **No public API change.**

## Bugs (verified)
- **State before bind.** `NexusServer.cs:226` sets the state to Running before the listener is created at `:236`. A bind failure therefore leaves the server Running with no listener, watchdog or collections.
- **Rate limiter lost on restart.** It is created only in `Configure` (`:184`), but disposed and nulled in Stop (`:309-310`). A restarted server runs without rate limiting.
- **One fault stops everything.** An accept-loop fault (`~:558-562`) stops the whole server.
- **Slow stop.** Stop disconnects sessions sequentially (`~:292-303`), each waiting a 200 ms `DisconnectDelay`.

## Owns
- `src/NexNet/NexusServer.cs` (**hot**)
- `src/NexNet/NexusServerState.cs` (append `Starting` and `Stopping`)
- `src/NexNet/INexusServer.cs` (no new members)
- `src/NexNet/Diagnostics/NexusServerSnapshot.cs`, if state is surfaced there
- tests: a new `src/NexNet.IntegrationTests/NexusServerTests_Lifecycle.cs`

## Steps
1. **Internal endpoints.** Introduce an internal `Endpoint {Config, Name, Tags, Listener, AcceptLoop, State}` list. Today it holds exactly one listener-mode endpoint, plus the implicit external/primary entry.
2. **One accept routine.** Extract the duplicated accept body (`~:345-389` and `~:496-553`) into a single method used by both the accept loops and `AcceptTransport`.
3. **Start:**
   - set state to `Starting`;
   - bind all endpoints;
   - on failure, close the bound ones, revert to `Stopped` and throw a `TransportException` naming the endpoint;
   - only then set `Running`, arm the watchdog and start collections.
4. **Rate limiter.** Create it in Start, not in Configure.
5. **Faults.** An accept-loop fault marks only its endpoint Faulted and logs. The server keeps running while any endpoint or external path is still alive.
6. **Stop:**
   - set state to `Stopping`, which gates accepts;
   - close listeners in parallel;
   - stop collections;
   - disconnect sessions in parallel, bounded at 64 concurrent;
   - dispose;
   - set `Stopped`.
7. **Tests:**
   - an AddressInUse bind failure leaves the server Stopped, and a later Start works;
   - rate limiting still applies after a restart;
   - stopping with 200 sessions finishes in under 5 s.

- The new tests pass.
- No public API change, apart from the two new enum values. Note them in the release notes.
